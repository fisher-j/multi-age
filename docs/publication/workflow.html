Development workflow

Overview, review sequence, and repository map

This overview describes the publication-development process. The task register and task list summarize the work, and each task has a dedicated review page. Each task is tracked like a small issue: it begins with an objective and guardrails, records the decisions and artifacts produced while it is open, and ends either in a reviewable manuscript product or a completed analytical record. The manuscript is developed backwards from the results displays: figures and tables → results → methods → discussion → introduction → abstract → title. This order adapts the “write backwards” approach described by Montagnes, Montagnes, and Yang (2022).

How to use this queue

Each dedicated task page preserves its proposal and detailed review record. Review and edit that proposal, then move the task through this sequence:

Direction for review → Approved to execute → In progress → Pending review → Accepted (or Revision requested) → Complete.

“Queued” means the task is deliberately decomposed and ready to be proposed; it is not yet authorized for execution. “Completed — analytical record” means the reproducible work is preserved, while a decision explicitly marked provisional still awaits scientific review. Page targets are working allocations for the main manuscript, not a journal requirement.

Task register and review records

The task register and task list are the current planning view. The register links to the task entries below it. Each entry summarizes the proposal or work documented on its dedicated page and links to relevant review sections. Full analytical records, figures, inference reviews, acceptance criteria, and current source/output files remain with that task.

Start with RD02 regeneration display review, RD04 fuel display and companion table, or RT03 fuel Results review. Their existing review states are preserved; reorganizing the website does not accept a scientific result.

Current local repository map

All paths are relative to the repository root. Linked files are served as downloadable copies of the current checkout, refreshed before every render. The download manifest records file checksums.

Repository location Purpose and current entry points
publication/ Website configuration, task pages, and draft section wrappers. Site maintenance guide.
publication/sections/ Shared manuscript sections and included review displays/tables. results.qmd and methods.qmd.
publication/tasks.json Task status, targets, summaries of the detailed task records, and current file lists. Task metadata.
publication/scripts/fuel/ Component derivation, model exploration, inference audit, and active integrated figure generator. Fuel pipeline guide.
publication/scripts/regeneration/ Selected separate-species models and historical sensitivity comparisons. Regeneration pipeline guide.
publication/outputs/ Publication-only derived data, model records, figures, tables, and provenance. Output conventions.
analysis/thesis/ and analysis/analysis/ Thesis prose and legacy analytical sources; linked from the tasks that use them. Repository overview.
docs/publication/ Rendered publication website; see the publication guide for rendering.

Keeping task records current

When work changes, update its dedicated task page first, then revise its entry in publication/tasks.json with a concise summary of that record, its current status, and exact repository file paths. Then render the publication. The pre-render step regenerates the register and summaries, refreshes linked file downloads, and fails if a referenced repository file has moved or disappeared. It reads existing analytical outputs without fitting models.

The manuscript section pages and full draft both include publication/sections/ sources. Edit those shared files once to update both reading views. Review decisions continue to follow the workflow above.

Documentation responsibilities

The analytical sequence starts with F01, followed by RD04 and RT03 Results writing. Each step’s executable QMD owns the detailed record: purpose/scope, inputs/dependencies, analyses performed, outputs/findings, decisions/rationale, implications/handoff, and review state/history. Update the originating step when its analysis or decision changes; downstream steps link to that record and explain their own use of it.

F01 owns fuel derivation, exploration, candidate fitting, and provisional model leaders. RD04 owns prediction/inference, uncertainty, the figure/estimates, and retired display history. RT03 owns the Results claims and qualifications. M03 and D03 will own manuscript Methods wording and management interpretation when their queued work begins. Consuming an upstream artifact does not transfer its ownership or accept its provisional scientific decisions.

For the developed fuel records, tasks.json separates produced outputs from consumed inputs and lists depends_on task IDs. Task introductions and file lists provide navigation; analytical explanations remain on their owning pages. Task summaries are concise descriptions of those records, not another decision log. The publication guide supplies operational commands and links back to the step documentation.

Calculation specifications and order live directly in each owning task page. Quarto selects whole pages for recomputation through native execution parameters; unselected pages review saved artifacts. There is no pipeline map, combined analytical account, or document-execution loop. See the maintenance guide for modes and validation.

Working boundaries

The standalone publication project remains separate from the legacy Quarto profiles in analysis/. Publication analyses write to publication/outputs/; their scripts live in publication/scripts/. Publication calculations consume committed thesis exports and use their own updated R and renv environment. Thesis-era model objects and raw data retain their established locations. Completion commits in task histories document past work; current-file links use the local checkout.
